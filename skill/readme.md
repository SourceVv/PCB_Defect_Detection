# PYNQ 检测工程复现与故障排查经验包

## 适用范围

面向 Python/Jupyter 控制 Overlay 与 AXI DMA 的项目，可复用目录迁移检查、界面空状态处理和参考比对流程。不是已经验证可移植到所有板卡的通用硬件驱动。

## 使用方法

1. 固定输入格式、字节数、输出形状、阈值和ABI，再编写软件参考。
2. 从 tests/test_full_inventory.py 中的注入服务模式建立独立测试，确认调用协议；注入测试不能证明DMA真实运行。
3. 用 scripts/smoke_test.py 验证已知样本，改变工程目录后再执行，检查绝对路径依赖。
4. 实物环境核对 bit/hwh 和驱动版本，在没有其他程序占用DMA时运行；保存原始返回数组与参考比对。
5. UI不加载时先区分前端控件故障与检测故障。空图片默认隐藏，替换输入后清除旧结果。

## 经验来源和已验证效果

早期 Notebook 将模型与图片写成几百万字符的长行，打开页面卡顿。模型独立存储后，启动入口约1KB；已检查启动代码和资源读取，但没有把文件变小等同于计算加速。

早期关闭网页后出现 VBox 文字。刷新并重新显示控件可以区分前端加载问题，不必反复初始化FPGA。此方法来自实际界面排查，不代表已覆盖所有浏览器版本。

Windows跨盘路径和旧配置会影响迁移。当前工程已在独立环境和另一临时目录通过示例检查；跨系统结果仍以CI和实机输出为准。

## 失效条件

ABI、硬件布局、DMA模式、缓存策略或板卡改变时，需要重新验证接口。图像内容、参考清单或标注不可靠时，脚本通过不能证明检测准确。没有实物和独立标签时，不能生成准确率或端到端性能结论。
