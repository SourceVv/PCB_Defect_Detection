## 2. 本轮性能实际改善了什么

先在同一块板卡测试5种等价的严格二值校验方法。每种都必须发现所有1—254中间像素，成功时返回白点数，没有跳过检查的性能选项。各预热3次，再正式测10次。

| 校验方法 | helper中位耗时 |
| --- | ---: |
| 原逐像素比较 compare | 249.014 ms |
| 求和证明 sum | 129.335 ms |
| 加1回绕 addwrap | 131.213 ms |
| 回绕后归约 addreduce | 187.493 ms |
| 字节计数 bytes_count | 115.650 ms |

`bytes_count` 先取得C顺序字节快照，统计0和255的个数。两种字节的数量相加必须等于全部像素数，才证明每个像素均为0或255；255的数量同时用来核对硬件白点数。它能发现128、134、254等错误值，与原规则同样严格。

同时去掉一份重复输出复制。冻结DMA驱动本来已经把收到的像素复制到独立NumPy内存，停止DMA并释放CMA后才返回。新服务在核对精确驱动源码、方法身份、完整拥有者数组和安全状态后，直接交出这份独立内存的拥有者；不能证明时仍复制。

这不是把已释放的DMA内存直接交给界面。实际验证中新服务33次均返回 `frozen_driver_owning_base`，输出对象自己拥有数据、`base=None`，并且不共享CMA。输入快照、二值/计数检查、帧编号、包状态、并发拒绝、超时和故障锁定都保留。

## 3. 完整调用对照：仍要如实看CPU基线

同一块PYNQ-Z2，同一张2533×1900 uint8灰度图，同一套17 ROI和阈值。CPU、旧服务、新服务采用固定种子的混排顺序，先预热3轮，再测30轮。旧新两服务每轮各做一次真实DMA，共66次。

| 口径 | 中位数 | P95 |
| --- | ---: | ---: |
| CPU NumPy参考 | 235.175 ms | 238.887 ms |
| 原v0.3.1完整服务 | 437.332 ms | 455.504 ms |
| 新v0.3.2完整服务 | 275.906 ms | 280.991 ms |

新服务比旧服务的中位耗时减少 **36.91%**，旧/新中位耗时之比约 **1.585**。新服务仍比本次CPU参考慢约 **17.32%**，所以目前不能宣称整个调用已经比CPU加速。

这里测的是完整服务调用，包含输入快照、DMA申请和缓存维护、输入输出复制、等待与停止、统计读取、状态和二值校验等。文件写入、输出摘要和额外黄金答案对比在主计时外。它不是纯FPGA算子时间，也不是相机端到端帧率。

固定ROI只配置一次。A的逐照片定位流程需要每帧映射和配置ROI，另有定位、服务初始化、分类、采集和显示开销，不能直接拿本表当整机周期。

全部66次DMA在板上完整比对mask与17项统计，均正确；完成包数为66，每次双通道停止后才释放内存。电脑另行核对全部记录、30次聚合、包序/安全字段以及保存的6份样本，独立审计通过。

## 4. 连续30分钟实际结果

**真实连续运行验收通过，电脑独立审计也通过。**

| 项目 | 实际结果 |
| --- | --- |
| 单调时钟持续时间 | 1800.478687 秒（超过30分钟） |
| 完整校验帧数 | 3,439 帧 |
| 数据/统计/超时错误 | 0 |
| 分钟检查点 | 30个，电脑按逐帧记录重新核对 |
| 最终状态 | ABI3，包数3439，busy/inpacket/cfg_error/frame_error均false |
| 最终驱动 | dma_safe=true，active/poisoned=false，活动和保留缓冲均0 |
| 保存的首末mask | 电脑逐字节与冻结答案一致 |

运行前后RSS为86768→91868 KiB；只看安全帧样本，首末为91668→91868 KiB（增加200 KiB）。CMA全局空闲前后11660→14148 KiB，总量131072 KiB。两种采样口径分别保留，不混用。逐帧记录全部随包保存，未保存每一帧的原始BIN，电脑对所有记录核验，并独立重比首末两份BIN。

本项范围是 **B的固定黄金图、17 ROI、DMA和服务链路**。每帧都做严格校验和完整黄金图比对，同时保存摘要、包计数、长度、停止状态和内存观测，分钟检查点写入报告。

它没有连接相机，也没有执行整套采集、放稳触发、定位、分类、界面和异常截图流程。因此即使本项通过，C仍需组织真实相机整机30分钟验收。

全量逐帧记录写入JSONL，不把全部记录累积在内存里。唯一帧编号集合会按设计增长，RSS峰值和全局CMA空闲也可能波动；报告保留观测值，不把一次测试写成内存泄漏的形式化证明。

## 5. C现在怎样调用优化版

本包新增 `final_roi_api.py`，使用唯一模块名加载本目录的新服务，避免旧同名模块已经导入时误用旧版。这个入口固定选择实测的 `bytes_count`。

```python
from final_roi_api import create_service

# driver由上层创建，已recover，并保证独占板卡。
service = create_service(
    driver, width=2533, height=1900, rois=rois,
    threshold=120, invert=True, roi_enable=True,
)
service.configure()
frame = service.process(gray, frame_id="capture-0001")
mask = frame["mask"]
areas = frame["roi_counts"]
```

这段代码不自动加载FPGA或复位硬件。`gray`和`rois`必须处在同一个坐标系；图像为二维uint8，形状为(高,宽)。frame_id不能重复。

原A流程没有把像素warp到参考坐标，它使用同一帧H映射ROI。需要接原A时，保留参考配置和模板框，使用原桥接层，注入新的服务工厂；不要把映射后的框写回原模板配置。

同一服务配置一次适合固定ROI。移动照片应由桥接每帧映射、重新配置；不能把固定框无条件套到所有原照片。不得同时让另一个Notebook或线程操作同一FPGA/DMA。

## 6. 已知分类误报仍然保留

上一轮18张开发照片的mask与计数全部正确，306项特征与原CPU相同；但252次缺件标签检查有1次误报、0次漏报。问题是 `s01_b03_3.jpg / U1`，原CPU和混合流程均得到SAD约20.398794，高于原阈值20.219，于是把存在器件判为缺件。

U1的SAD仍由CPU计算，本轮没有把它替换成PL面积，也没有调整阈值。本轮优化只改严格校验方法和冗余复制，不能据此声称修复了A的分类问题。历史包的 `failed_stopped / passed:false` 原报告保持不变。

A需要复现定位、模板、阈值和历史环境差异，再用新拍摄样本验证。现有18张都是开发图，不能把开发回放称作独立测试准确率。明显错位、焊反/倾斜、无板/遮挡等整机能力应由A/C分别提供实际证据。
