# FPGA 图像算子与 PS/PL 联调实现（成员 B）

本章节可供 C 合并到项目技术报告。成文日期为 2026-11-01；已完成部分均以保存的构建、仿真、实板与电脑复核记录为依据。本轮新增优化、66 次真实 DMA 对照、1800.478687 秒/3,439 帧连续运行及发布核心核验均已完成，正文已回填实际结果；A 的已知误报与 C 的相机整机范围继续独立列明。

## 1. 设计目标与职责划分

本项目采用 PYNQ-Z2 的 Zynq-7020，将图像定位与缺陷判定保留在处理器系统 PS，将规则明确、适合流式处理的灰度反相、严格阈值、矩形 ROI mask 和前景面积统计交给可编程逻辑 PL。

成员 B 负责最小 DMA 工程、RTL 算子、仿真、Vivado 集成与实现、寄存器接口、配对 bit/hwh、时序与资源报告，并与系统软件共同验证 DMA。A 提供照片、标签、ROI 与软件参考；C 负责相机、系统界面、触发、显示与交付整合。本章节中的文件回放和硬件路径测试，不等同于相机整机验收。

硬件最终接口为 ABI3，发布工程为 `pcb_b_roi_v03`。本轮 v0.3.1/v0.3.2 是软件联调与测量工作包版本，未据此改变 RTL、时钟或硬件寄存器协议。

## 2. 系统结构与数据通路

### 2.1 PS/PL 分工

```text
PS software
  image -> BGR-to-gray -> A alignment H -> mapped/clipped ROI
                    |                           |
                    v                           v
                  DDR                     GP0 control path
                    |                     /       |       \
                    |                DMA regs  ctrl GPIO  cfg GPIO
                    v
             AXI DMA MM2S -- AXIS32 --> PL ROI/threshold/stats
                    ^                          |         |
                    |                          |         +--> stats GPIO
              HP0 / AXI memory                 v
                    |                 AXIS32 -> AXI DMA S2MM
                    |                              |
                    +------------- DDR <-----------+
                                    |
                                    v
                     PS mask/count checks -> A classification
                                    |
                         display/logging by C system
```

PS 经 GP0 与控制互连访问 DMA 和两个 GPIO；DMA 的 MM2S/S2MM 经内存互连连接 HP0，访问 DDR。MM2S 将输入灰度送入 PL，S2MM 将同尺寸二值 mask 写回 DDR。面积统计通过 GPIO 选择地址读取，而不是混入图像字节流。

PL 使用 PS FCLK0 提供的 100 MHz 时钟。DMA、GPIO、互连和图像模块使用统一时钟域，复位通过 proc_sys_reset 分配。没有将每行视频 TLAST 直接用于简单 DMA，避免 DMA 把第一行误当成完整传输。

### 2.2 DMA 与像素格式

| 项目 | 发布配置 |
|---|---|
| 器件 / 工具 | xc7z020clg400-1 / Vivado 2025.2 |
| DMA 模式 | 双向 Simple DMA；无 SG、无 DRE |
| DMA 内存侧 / 流侧宽度 | 64 bit / 32 bit |
| 地址 / 长度字段 | 32 bit / 23 bit |
| 图像输入 | 单通道 uint8，形状为 `(height,width)` |
| AXI Stream | TDATA32、TKEEP4、TVALID/TREADY、整帧一次 TLAST |
| 字节顺序 | 最早像素放 TDATA[7:0]，按 lane0 到 lane3 连续排列 |
| 当前完整测试帧 | 宽 2533、高 1900，共 4,812,700 字节 |
| 每完整帧流拍数 | 1,203,175 拍，整帧长度为 4 的倍数 |

2533 不是 4 的倍数，因此某一 32 位数据拍可能包含相邻两行的像素。硬件根据有效 KEEP 字节紧密推进光栅坐标，不在行尾填充字节；TLAST 只标记整帧最后一拍。软件拒绝非 uint8、错误形状、超出长度限制或不符合当前 4 字节长度约定的输入。

## 3. ROI 阈值与面积统计 RTL

核心模块为 `axis_roi_threshold_stats`，一次最多配置 17 个矩形。矩形按左闭右开 `[x0,x1)×[y0,y1)` 定义。反相使能时先计算 `255-g`，之后执行严格大于比较：`pixel > threshold` 时输出 255，否则输出 0。

在当前阈值 120、反相使能条件下，前景等价于 `g<135`，所以 g=134 为白色，g=135 和 g=136 为黑色。ROI 模式开启时仅保留启用区域的并集；模式关闭时输出全图阈值结果，同时仍可读取各 ROI 的前景计数。

单 ROI 前景计数独立累加，重叠像素可以同时属于多个区域；联合 mask 的前景数只计同一输出像素一次。因此不能将 17 个 ROI 计数直接相加作为联合图的白点总数。旁路模式原样转发有效字节，跳过反相/阈值/ROI 判断，前景统计按协议为 0，但有效输入像素数仍统计。

核心将坐标推进、ROI 比较与统计计算分成寄存阶段。当前最终实现理想无反压时最小输入接收间隔为 3 个时钟；当输出未被接收时保持数据、KEEP 与 LAST 稳定。该协议行为用 VALID/READY 处理上下游暂停，不据此估算相机持续帧率或整机速度。

宽高为 0、提前 LAST、多余有效像素等会置 frame_error；统计结果只在输出 TLAST 真正握手时提交，避免 PS 读取到未完成的一帧。16 位完成包数允许回绕，软件按模 65536 求差验证一次调用仅完成一个包。外部复位清配置；软复位清流状态和统计但保留已配置几何。

## 4. 寄存器与调用契约

### 4.1 控制与状态

| 字段 | 定义 |
|---|---|
| ctrl[7:0] | 8 位像素阈值 |
| ctrl[8] / ctrl[9] | 旁路 / 电平软复位 |
| ctrl[10] / ctrl[11] | 反相 / ROI 联合输出使能 |
| ctrl[12] | 配置写请求 toggle |
| ctrl[23:16] | 配置写入或读取选择地址 |
| status[15:8] | 硬件 ABI，当前为 3 |
| status[31:16] | 已完成输出包数，16 位回绕 |
| status[0] / status[1] | busy / inpacket |
| status[2] / status[3] / status[4] | 配置 ack / cfg_error / frame_error |

尺寸、ROI enable 位图、各 ROI 坐标通过配置地址写入；输出白点数、有效像素总数和 ROI 计数通过选择地址读取。具体寄存器表见冻结接口文件 `pcb_b_roi_v03/config/interface_v03.md`。

配置时先写数据 GPIO，再更新地址并翻转请求 token，保持数据/地址/token，直到 ack 对齐且 busy 清零。硬件拒绝运行中写入，避免一帧混用两组 ROI。配置与统计读取均由单一硬件所有者执行。

### 4.3 软件安全边界

RoiDriver 负责图像缓冲区分配、地址与长度检查、输入 flush、输出 invalidate、先启动接收再发送、完成条件检查和超时恢复。传输返回前确认双通道停止，才释放可能被 DMA 访问的缓冲区；若无法确认停止，则进入 poisoned 并保留内存，禁止继续调用。上层执行器在此情况下保留进程，由明确的硬件停止流程处置，避免关闭内核使仍被硬件访问的内存释放。

AoiRoiService 将一帧图像、命名 ROI 计数、完成包、状态和 frame_id 绑定为同一结果，拒绝并发、重复帧编号和统计身份不一致。Python 锁只覆盖该服务实例，不能约束另一个 Notebook/进程，系统必须保持一个硬件所有者。服务异常后停止接收新帧，不隐式重载 FPGA、恢复或用软件结果冒充硬件结果。

## 5. 与 A 原算法的坐标和特征对接

A 的 `prepare_frame()` 返回当前灰度图与参考坐标到当前输入坐标的 H，并未透视矫正像素。桥接层采用原 `map_box()` 将参考 ROI 四角映射后，按 floor/ceil 取外接矩形并裁边，再配置 PL。输入像素仍是原灰度，不额外 warp，也不对映射后的框再次应用 H。

原 A 配置框保持不变，另存硬件映射框；否则 SAD/hcorr 会错误地从参考图的映射位置裁模板。输入图无效、定位失败、H 非有限值或映射 ROI 为空时，在进入硬件前停止本帧，交由系统提示重新放置，不能继续把所有区域判作缺件。

| 特征或步骤 | 本轮归属 | 处理方式 |
|---|---|---|
| 原灰度反相/严格阈值/ROI mask/17 区域前景计数 | PL | 一次整帧处理 |
| area_inv 的 feat | PL 计数接入 | 当前仅 U2、SW2 属于缺件面积分类；另有 C14/C17/C24 默认面积特征 |
| area 字段 | CPU | 仍计算原灰度 `<100` 像素数，不能用 PL `<135` 计数覆盖 |
| 5 项 SAD、3 项 hcorr、4 项 cd40 | A 原 CPU 函数 | 保留原 resize/模糊/模板/直方图/中心窗规则 |
| 定位、分类阈值与状态规则 | PS / A 原规则 | 未将全部区域改成面积分类 |

像素阈值 threshold_inv 默认 120，与某器件最终特征判定 threshold 是两个不同参数。桥接核对全部 area_inv 的像素规则相同，才用单次 PL 全局模式替换。验收时对同一灰度、同一个 H 再调用原 CPU 函数比较，避免重跑随机定位导致取样区域不同。

### 9.2 本轮新增优化与连续运行

本轮同板微测与新旧服务对照已实际完成，硬件仍使用原 ABI3，五项 runtime 源冻结不再修改。严格二值检查采用 `bytes_count`：将 C 顺序字节快照中 0 和 255 的数量相加，要求恰好等于像素数，并以 255 数量作为白点数；中位数为 115.650 ms，原 `compare` 为 249.014 ms。两者都证明整个输出为二值并计算白点数，并未用抽样替代每帧完整检查。
